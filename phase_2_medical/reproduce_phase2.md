# reproduce_phase2.md

## Purpose

This document records the procedure used to reproduce the archived Phase-2 medical QA scoring artifacts, metrics, and downstream analysis outputs in this repository.

Phase 2 evaluates whether white-box signals from the Phase-1 setting remain useful for benchmark-defined prediction error detection in constrained medical QA under a frozen-output protocol.

---

## Reproduction Scope

Phase 2 reproduction covers:

- baseline scorer runs (MedQA/PubMedQA x Mistral/BioMistral)
- manifests and bootstrap index artifacts
- deterministic table/figure generation
- optional ablation runs

It does **not** cover:

- model fine-tuning
- calibration pipelines
- generation-time mitigation/intervention methods

The resulting artifacts should therefore be read as evidence about ranking-based error discrimination under constrained benchmark supervision, not as a direct reproduction of free-form medical hallucination detection.

---

## Canonical Artifact Rule

For reported baseline results, canonical artifacts are:

- `phase_2_medical/outputs/final/*.results.jsonl`
- `phase_2_medical/outputs/final/*.manifest.json`
- `phase_2_medical/outputs/final/*.manifest.bootstrap_indices.npz`

If these files already exist and match expected naming, use them as the reference inputs for analysis regeneration.

In the current repository state, the four Phase-2 baseline bootstrap index files under `phase_2_medical/outputs/final/` are present. The repository-wide size policy still ignores `*.npz`, so additional locally generated `.npz` artifacts are not guaranteed to be tracked in future clones or exports.

For exact CI reproduction, bootstrap index files can:

- be used directly from the tracked baseline artifacts in this repository state, or
- be provided in the accompanying submission archive, or
- be regenerated by rerunning the baseline pipeline with the same bootstrap budget (e.g. `--B 5000`).

## Protocol Overview

The reported Phase-2 results follow a two-stage workflow:

1. model outputs are generated once for each dataset-model pair and stored as frozen JSONL artifacts under `phase_2_medical/outputs/frozen/`
2. scorer extraction and evaluation are then run post hoc on these archived outputs under teacher forcing

The released artifacts and thesis documentation support the following operational summary:

- frozen generations are free-form continuations rather than native benchmark labels
- constrained parsing maps each continuation to the benchmark label space by extracting the first valid answer match
- the label space is task-specific: `A`-`D` for MedQA and `yes`/`no`/`maybe` for PubMedQA
- if constrained parsing fails, the frozen `model_answer` text is retained as the teacher-forced answer sequence for scorer-side extraction
- baseline scorer-side context budgets are task-specific: `64` tokens for MedQA and `128` tokens for PubMedQA

Truncation distinction:

- frozen prediction artifacts may record generation-side metadata such as `prompt_truncation_max_length`
- scorer reruns use scorer-side context limits such as `--max_context_tokens`
- these refer to different stages of the pipeline and should not be treated as interchangeable

Prompt note:

- the released Markdown documentation does not restate the full Phase-2 prompt text
- for thesis-level result verification, the frozen prediction files remain the authoritative inputs

## Environment

Minimum:

- Python `>= 3.10`
- Dependencies from repo root:

```bash
pip install -r requirements.txt
```

Execution assumptions:

- GPU is recommended for gradient and hidden-feature extraction.
- Hugging Face access token may be required depending on model availability.
- maintained batch entrypoints are documented as `bash` scripts and therefore assume a Linux-like shell environment
- Linux or WSL are the intended environments for the maintained `bash` runners; the direct Python CLI example below avoids the `bash` dependency for single-run reproduction

Hardware note: running the full scoring pipeline for 7B models typically requires a GPU with >=24GB VRAM. The reference runs were executed on an NVIDIA A100 (80GB).

Optional `.env` in repo root:

```bash
HF_TOKEN=...
```

Some runner scripts map `HF_TOKEN` to `HUGGINGFACE_HUB_TOKEN`.

## Determinism Notes

The pipeline is designed for high reproducibility via:

- frozen input predictions
- fixed seeds in baseline configurations
- serialized bootstrap indices per run
- deterministic analysis scripts over archived artifacts

Practical note:

- very small floating-point deviations may occur across runtime/library/hardware environments.
- canonical reported outputs are defined by archived files under `outputs/final/`.

---

## Evaluation Guardrails (High Level)

The evaluation pipeline includes several validity controls intended to prevent silent failures:

- scorer outputs are checked for non-finite values such as `NaN` or `Inf`
- degenerate constant score vectors are rejected where ranking metrics would otherwise be undefined or uninformative
- invalid examples and exclusions are tracked explicitly for auditability
- raw score outputs are preserved prior to polarity alignment or aggregate summarization where applicable

These controls support artifact-level auditability, but the archived result files remain the reference source for reported thesis numbers.

## Direct CLI Reproduction (Single Run Example)

For a single run directly via Python:

```bash
python phase_2_medical/src/run_phase2.py \
  --task pubmedqa \
  --frozen_jsonl phase_2_medical/outputs/frozen/pubmedqa_mistral7b.jsonl \
  --out_jsonl phase_2_medical/outputs/final/pubmedqa_mistral.B5000.results.jsonl \
  --out_manifest phase_2_medical/outputs/final/pubmedqa_mistral.B5000.manifest.json \
  --model_name mistralai/Mistral-7B-Instruct-v0.2 \
  --device cuda:0 \
  --dtype bfloat16 \
  --seed 42 \
  --n_splits 5 \
  --B 5000 \
  --ci 0.95 \
  --batch_size 4 \
  --hidden_batch_size 4 \
  --max_context_tokens 128
```

For baseline comparability, prefer the script values in `run_baseline_all.sh`.

- Missing HF auth for model loading
- Running from wrong working directory
- Overwriting previously archived outputs unintentionally
- Mixing environments (library versions) and expecting bit-identical probe scores
